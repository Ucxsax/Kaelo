# Kaelo 桌面视觉自动化系统 - Product Requirement Document

## Overview
- **Summary**: 一款轻量化桌面视觉自动化闭环项目，本地程序实时捕获屏幕、构建全局坐标体系，将画面图像+元素坐标同步发送给AI智能体；AI根据画面内容与用户需求生成标准化操作指令，本地程序解析并自动执行键鼠操作，实现视觉识别—坐标分发—AI决策—本地执行全自动链路。
- **Purpose**: 实现桌面界面的自动化操作，通过视觉识别和AI决策完成用户指定的任务。
- **Target Users**: 个人用户、需要桌面自动化辅助的工作者。

## Goals
- 实现屏幕实时捕获与可交互元素识别
- 构建全局统一坐标体系
- 实现AI智能体决策与指令生成
- 实现本地程序指令解析与安全执行
- 实现完整的闭环循环工作流程

## Non-Goals (Out of Scope)
- 不实现文档未定义的功能
- 不新增未被明确授权的指令
- 不修改项目已定义的闭环工作流程
- 不突破文档中设定的安全限制与操作边界
- 不实现文件删除、系统修改、格式化、权限篡改等高危操作

## Background & Context
- 项目采用多Agent协作架构：
  - AGENT-SCREEN（画面识别）：屏幕捕获 + 元素识别与坐标生成
  - AGENT-COMM（通信）：数据格式化 + 数据转发 + 指令校验
  - AGENT-DECISION（决策）：AI决策 + 单步指令生成
  - AGENT-EXEC（执行解析）：指令解析子模块 + 安全校验子模块 + 操作执行子模块
- 技术栈：
  - 视觉捕获：使用 Python mss 或 PIL.ImageGrab
  - 元素识别：使用 OpenCV + 模板匹配或 UI Automation
  - 自动化引擎：使用 PyAutoGUI 实现键鼠操作
  - 通信方式：使用 OpenAI API 作为默认AI服务（支持扩展）
  - 运行环境：Windows
- 核心工作流程：屏幕捕获 → 元素识别 & 坐标构建 → 图像+坐标数据推送AI → AI生成操作指令 → 本地安全校验 → 指令解析执行 → 循环刷新画面 / 任务结束

## Functional Requirements
- **FR-1**: 屏幕捕获模块实时截取完整屏幕画面
- **FR-2**: 画面识别模块自动识别按钮、输入框、图标、窗口等可交互区域并生成标准坐标
- **FR-3**: 通信模块格式化打包数据并转发给决策AI
- **FR-4**: 决策AI根据画面和用户需求生成单步操作指令（click/wait/end）
- **FR-5**: 指令解析子模块解析指令类型与参数
- **FR-6**: 安全校验子模块校验指令安全性并拦截高危操作
- **FR-7**: 操作执行子模块执行实际键鼠操作
- **FR-8**: 系统实现完整的闭环循环工作流程

## Non-Functional Requirements
- **NFR-1**: 系统具备完善的异常捕获机制（截图失败、网络异常、AI返回格式错误、执行超时、元素识别失败、AI返回空指令/多指令、键鼠操作被系统拦截、用户手动中断等）
- **NFR-2**: 坐标体系统一使用屏幕绝对坐标，支持多显示器场景（主显示器(0,0)，副显示器坐标基于主显示器偏移），支持高DPI屏幕适配（自动处理Windows DPI缩放）
- **NFR-3**: 单步指令执行模式，复杂任务分步执行
- **NFR-4**: 严格的安全约束，拒绝高危系统操作
- **NFR-5**: 屏幕捕获分辨率与屏幕一致，帧率≥1fps，延迟≤500ms
- **NFR-6**: click操作坐标误差≤±5像素
- **NFR-7**: 通信异常重试3次，重试间隔1s，连续失败3次终止任务
- **NFR-8**: 元素识别准确率≥95%，坐标生成耗时≤100ms
- **NFR-9**: 代码适配主流 Windows 桌面环境（Windows 10/11）

## Constraints
- **Technical**: 运行环境为Windows，必须严格遵循5个文档中定义的所有规范
- **Business**: 仅用于个人学习、本地自动化辅助使用，禁止用于恶意操作
- **Dependencies**: 模块化架构，屏幕捕获、坐标计算、AI通信、指令解析、安全校验、操作执行独立拆分

## Assumptions
- 决策AI智能体能够正确理解屏幕画面和用户需求
- 本地程序与AI之间的通信稳定可靠
- 屏幕捕获和元素识别能够准确获取可交互元素
- 用户拥有足够的Windows权限执行键鼠操作

## Acceptance Criteria

### AC-1: 屏幕捕获功能正常
- **Given**: 系统已启动运行
- **When**: 执行屏幕捕获操作
- **Then**: 能够成功截取完整、清晰的屏幕画面，分辨率与屏幕一致，延迟≤500ms
- **Verification**: `programmatic`
- **Notes**: 画面卡顿/捕获失败时自动重试，最多重试3次

### AC-2: 元素识别与坐标生成
- **Given**: 屏幕已成功捕获
- **When**: 执行元素识别
- **Then**: 能够识别按钮、输入框、图标、窗口等可交互区域，识别准确率≥95%，并为每个区域生成标准坐标（X、Y、宽、高），坐标生成耗时≤100ms
- **Verification**: `programmatic`
- **Notes**: 忽略无效背景区域，只保留可交互有效元素；支持多显示器和高DPI屏幕

### AC-3: 数据格式化与通信
- **Given**: 已获取屏幕画面和元素坐标
- **When**: 通信模块处理数据
- **Then**: 能够标准化压缩打包数据，过滤无效数据，转发至决策智能体
- **Verification**: `programmatic`
- **Notes**: 通信异常时触发重试机制，重试3次，间隔1s，连续失败3次终止任务

### AC-4: AI决策生成单步指令
- **Given**: 决策智能体接收到画面、坐标、用户需求、历史操作记录
- **When**: 决策智能体处理数据
- **Then**: 仅输出纯指令内容（click/wait/end），无解释、无科普、无多余文字；一轮对话只输出单步操作；所有操作匹配画面真实元素；严格使用坐标定位/元素名称定位两种标准格式
- **Verification**: `programmatic`
- **Notes**: AI不会生成高危指令

### AC-5: 指令解析
- **Given**: 接收到AI返回的指令
- **When**: 指令解析子模块处理指令
- **Then**: 能够识别指令类型（click/wait/end），解析坐标参数、目标元素、等待时长等关键数据
- **Verification**: `programmatic`
- **Notes**: AI返回空指令或多指令时，终止任务并提示

### AC-6: 安全校验
- **Given**: 指令已解析
- **When**: 安全校验子模块校验指令
- **Then**: 能够拦截高危违规操作指令，未知指令直接忽略，坐标越界、元素不存在时放弃操作并上报异常
- **Verification**: `programmatic`
- **Notes**: 所有操作基于实时屏幕画面判定，杜绝无依据盲目操作

### AC-7: 操作执行功能
- **Given**: 指令已通过安全校验
- **When**: 操作执行子模块执行实际操作
- **Then**: 能够精准调用本地键鼠接口完成click操作（坐标误差≤±5像素）、wait操作；end指令触发后立即停止所有循环与后台监听
- **Verification**: `programmatic`
- **Notes**: 操作完成后反馈执行结果，触发下一轮画面刷新循环；键鼠操作被系统拦截时，终止任务并提示

### AC-8: 完整闭环循环
- **Given**: 系统已启动且有用户需求
- **When**: 执行完整工作流程
- **Then**: 能够循环运行：屏幕捕获→元素识别→数据推送→AI决策→指令解析→安全校验→指令执行→画面刷新，直至任务完成
- **Verification**: `programmatic`
- **Notes**: 严格遵循单向数据推送，无额外冗余功能；支持用户手动中断流程

### AC-9: 安全约束执行
- **Given**: 系统接收到指令
- **When**: 指令包含高危操作
- **Then**: 系统拒绝执行该指令
- **Verification**: `programmatic`
- **Notes**: 高危操作包括但不限于：修改注册表、修改环境变量、格式化磁盘、删除系统文件、篡改系统权限、启动/终止系统进程、写入/读取敏感文件等

### AC-10: 异常处理完整性
- **Given**: 系统运行中发生异常
- **When**: 异常场景发生
- **Then**: 系统能够正确捕获并处理异常，不会崩溃
- **Verification**: `programmatic`
- **Notes**: 覆盖的异常场景包括：截图失败、网络异常、AI返回格式错误、执行超时、元素识别失败、AI返回空指令/多指令、键鼠操作被系统拦截、用户手动中断

### AC-11: 多显示器与高DPI适配
- **Given**: 系统在多显示器或高DPI环境运行
- **When**: 执行坐标相关操作
- **Then**: 坐标计算正确，操作精准
- **Verification**: `programmatic`
- **Notes**: 多显示器场景：主显示器(0,0)，副显示器坐标基于主显示器偏移；高DPI场景：自动处理Windows DPI缩放

### AC-12: Windows环境适配
- **Given**: 系统在Windows环境运行
- **When**: 执行任意操作
- **Then**: 系统正常运行
- **Verification**: `programmatic`
- **Notes**: 适配主流 Windows 桌面环境（Windows 10/11）
